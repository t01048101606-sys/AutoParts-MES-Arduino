## 1. 프로젝트 개요

자동차부품 제조 공정을 관리하는 생산관리시스템(MES)입니다. 이전에 만든 "라면공장 Mini MES"의 핵심 구조(품목-LOT-생산-검사-출하)를 재사용하되, 자동차부품 업종 특성에 맞춰 **다단계 공정(라우팅) 관리**와 **개별 부품 시리얼 추적** 기능을 추가로 설계·구현했습니다.

**기술 스택**
- Frontend/App: Python, Streamlit
- Database: SQLite
- 인증: 아이디/비밀번호 해시(SHA-256) 기반, 역할별(ADMIN/OPERATOR/INSPECTOR) 접근 제어

---

## 2. 문제 정의 — 왜 이 구조로 설계했는가

자동차부품은 라면 같은 단일 공정 제품과 달리, 실무에서 다음과 같은 요구사항이 추가로 필요합니다.

- "이 부품은 프레스 → 용접 → 도장을 거치는데, 지금 어느 단계까지 진행됐지?"
- "이 원자재 로트에 문제가 생겼는데, 어떤 완제품(그리고 몇 번 시리얼)까지 영향을 미쳤지?"
- "이 도면번호/재질규격에 맞게 만들어졌는지 스펙을 어디서 확인하지?"
- "완성차 업체가 특정 부품 하나의 이력(전 공정, 전 원자재)을 요구하면 어떻게 답하지?"

단일 공정 구조로는 이런 질문에 답할 수 없었기 때문에, **공정 순서(라우팅)** 와 **개별 시리얼 추적**이 가능한 구조로 새로 설계했습니다.

---

## 3. 시스템 구조

**핵심 데이터 흐름**

```
품목/거래처/공정/설비 등록 → 라우팅·BOM 설계 → 원자재 입고
    → 작업지시 → 공정 실행(단계별 반복) → 검사 → 개별 시리얼 부여 → 출하 → LOT 추적
```

기존 라면 MES와의 가장 큰 차이는 "생산"이 한 번에 끝나지 않고 **공정 단계 수만큼 반복**된다는 점입니다.

## 4. 핵심 기능

| 기능 | 설명 |
|---|---|
| **라우팅/BOM 관리** | 제품이 거칠 공정 순서를 단계별로 등록(예: 1.프레스→2.용접→3.도장), 각 단계별 필요 원자재를 BOM으로 연결 |
| **공정 실행** | 작업지시를 고르면 다음에 실행할 단계가 자동 계산되어 표시. 단계 건너뛰기는 시스템이 차단 |
| **개별 시리얼 관리** | LOT 단위 추적으로 부족한 안전부품 등을 위해 부품 하나하나에 시리얼번호 부여 |
| **LOT 추적** | 원자재 LOT 하나를 정방향 추적하면 전체 공정을 거쳐 어떤 완제품이 됐고 어디로 출하됐는지 한 번에 조회. SQLite `WITH RECURSIVE` 재귀 쿼리로 구현 |
| **출하 관리** | 완제품 LOT만 대상, 불합격(FAIL) 판정 LOT는 자동으로 출하 차단 |
| **홈 대시보드** | 작업지시별 진행률, 원자재 재고 알림, 최근 활동 타임라인 |

## 6. 기술적으로 고민했던 지점

> 발표 때 준비했던 Q&A를 "고민 과정"으로 재구성한 부분입니다. 실제 인터뷰에서도 그대로 쓰기 좋습니다.

**왜 SQLite를 선택했는가**
소규모 시스템이라 별도 서버 없이 파일 하나로 관리 가능하다는 점을 고려했습니다. 실제 운영 규모라면 PostgreSQL 등으로 전환할 수 있는 구조로 설계했습니다.

**라면공장 MES 대비 가장 큰 구조 변화**
생산이 한 번에 끝나지 않고 공정 단계(라우팅) 수만큼 반복되는 점입니다. 그래서 `production` 테이블 하나였던 것을 `routing` / `routing_step` / `work_order` / `operation` 네 개로 분리했습니다.

**BOM을 제품이 아닌 공정 단계에 연결한 이유**
원자재가 "제품 전체"가 아니라 "몇 번째 공정에서" 투입되는지가 중요했기 때문입니다. 1단계에서 강판이 들어가고 3단계에서 도료가 들어가는 식으로 공정별 투입 자재가 다릅니다.

**LOT 추적을 재귀 쿼리로 구현한 이유**
공정 단계 수가 제품마다 다를 수 있어서, 몇 단계든 자동으로 끝까지 따라가려면 SQL의 `WITH RECURSIVE` 재귀 쿼리가 필요했습니다.

**보안 처리**
비밀번호는 평문 저장 없이 솔트+SHA-256 해시로 저장하고, 역할(ADMIN/OPERATOR/INSPECTOR)에 따라 페이지 접근을 제한했습니다.

---

## 7. 확장 가능성

이 구조는 라면공장 MES에서 시작해, 다단계 공정과 개별 시리얼 추적이 필요한 업종(자동차부품, 전자부품 등)에 맞게 확장한 결과입니다. 반대로 라우팅이 항상 1단계인 업종에서는 라면 MES 쪽 구조가 더 단순하고 적합합니다. 즉 업종 특성에 따라 두 구조 중 선택하거나, 필요할 때 라우팅을 도입하는 방식으로 점진적 전환이 가능합니다.

# 스마트 제조 프로젝트 여정: MES 구축부터 AI 품질검사 확장까지

> 라면공장 MES → 자동차부품 MES(라우팅/시리얼 추적/IoT 센서 연동) → AI 기반 품질검사(진행중)로 이어지는 프로젝트 흐름을 정리한 문서입니다.

---

## 1. 전체 흐름 한눈에 보기

| 단계 | 프로젝트 | 상태 | 핵심 내용 |
|---|---|---|---|
| 1 | 라면공장 Mini MES | ✅ 완성 | 단일 공정 MES 기본 구조 (품목-LOT-생산-검사-출하) |
| 2 | Auto Parts MES | ✅ 완성 | 다단계 공정(라우팅) + 개별 시리얼 추적 + 아두이노 센서 연동 |
| 3 | AI 품질검사 (하리보 젤리 CNN) | 🔄 진행중 | 컴퓨터 비전 기반 불량 자동 판정 — MES 검사 모듈과 연동 목표 |

세 프로젝트는 독립된 과제가 아니라 하나의 방향으로 이어집니다. **"사람이 눈으로 보고 입력하는 MES"에서 "센서와 AI가 스스로 데이터를 채우는 MES"로 확장**하는 흐름입니다.

---

## 2. 왜 이 순서로 진행했는가

MES를 먼저 만든 이유는, AI가 아무리 정교해도 그 판정 결과를 저장하고 추적할 시스템이 없으면 실무에서 의미가 없기 때문입니다.

- 라면 MES에서 **품목-LOT-생산-검사-출하**라는 기본 뼈대를 먼저 검증
- Auto Parts MES에서 **다단계 공정 추적 + 개별 시리얼 + 실시간 센서 데이터(충격/온습도/카운터)** 를 추가해, "현장에서 자동으로 데이터가 쌓이는" 구조로 확장
- 이 위에 **AI가 불량을 자동으로 판정해서 그 결과를 검사(INSPECTION) 테이블에 자동으로 기록**하는 것이 다음 목표

즉 AI 프로젝트는 별개의 과제가 아니라, **이미 만들어둔 MES의 검사 모듈에 꽂아 넣을 "자동 판정 엔진"** 을 만드는 작업입니다.

---

## 3. Auto Parts MES 요약 (완성)

*(상세 내용은 별도 README.md 참고)*

- Python + Streamlit + SQLite 기반, 다단계 공정(라우팅)과 개별 부품 시리얼 추적 지원
- 아두이노 센서 보드(충격/초음파/온습도/리드센서) 연동 완료 — 현장 모니터링 페이지에서 실시간 데이터 수신 및 경보, 생산 카운터 자동화
- 핵심 흐름: 기준정보 → 라우팅/BOM → 입고 → 작업지시 → 공정실행 → 검사 → 시리얼 → 출하 → LOT 추적
- 검사(INSPECTION) 테이블은 현재 **사람이 PASS/FAIL을 직접 입력**하는 구조 → 이 지점이 AI 프로젝트와 연결되는 접점

## 4. AI 프로젝트 진행 상황 (진행중)

### 4-1. 인공지능 수업 팀 프로젝트 (하리보 젤리)

**목표**
자동차부품/철강 등 실무형 타겟 업종의 품질검사에 쓰일 수 있는, 컴퓨터 비전 기반 불량 판정 모델을 만드는 것이 최종 방향입니다. 우선 데이터 수집이 쉬운 하리보 젤리를 대상으로 CNN 분류 모델을 먼저 검증하기로 했습니다.

**현재까지 진행된 것**
- 팀원별로 카메라(Intel RealSense) 배분 완료

- 하리보 젤리를 대상으로 데이터(이미지) 촬영/수집 계획 수립
- CNN 방식으로 분류 모델을 만들 예정

**아직 안 된 것 (앞으로 할 일)**
- 실제 데이터 촬영/라벨링
- CNN 모델 설계 및 학습

- Auto Parts MES 검사 모듈과의 연동 방식 설계 (예: 모델 추론 결과를 `inspection.result`에 자동 기록)

## 5. 두 프로젝트가 만나는 지점 (연결 설계 — 구상 단계)

MES와 AI를 실제로 연결한다면 다음과 같은 흐름이 될 것으로 예상합니다. *(아직 구현 전, 설계 방향 메모)*

```
카메라(RealSense)로 부품/제품 촬영
    → CNN 모델이 양품/불량 판정
    → 판정 결과를 Auto Parts MES의 검사(INSPECTION) 테이블에 자동 저장
    → 기존 로직 그대로 적용 (불량 사유코드 매핑, FAIL LOT 출하 자동 차단)
```

기존 MES에서 사람이 하던 "검사 결과 입력"이라는 한 단계만 AI로 대체하는 구조라, **이미 완성된 MES 구조를 크게 바꾸지 않고도 AI를 얹을 수 있다는 점**이 이 프로젝트 흐름의 강점입니다.
